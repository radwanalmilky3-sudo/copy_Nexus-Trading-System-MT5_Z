# Strategy / ML Layer Comparison — Reference (fx-trading-system) vs Nexus (nexus-ml + nexus-agents)

Author: A9 (Strategy Comparator). READ-ONLY analysis; no source files were modified.
Scope: Reference = `fx-trading-system-main/src/fx_system/` (strategies/base.py, strategies/technical.py, strategies/multicurrency.py, factor_research.py, long_horizon_runner.py, tests/test_strategies.py). Nexus = `services/nexus_ml/main.py` (plus its training/promotion/ensemble modules as read context) and `services/nexus_agents/main.py` (plus its research/registry/evaluator modules as read context).

## Strategy contract / interface comparison

The reference system defines a deliberately minimal and strict strategy contract: an abstract `Strategy` class with a single method `generate(Mapping[symbol, DataFrame]) -> list[Signal]`, where `Signal` is a rich value object carrying timestamp, symbol, side, confidence, strategy name, ATR, stop_atr, target_atr, max_holding_hours, a human-readable reason, and an optional group_id for multi-leg structures (e.g., the two cointegration legs emitted atomically under one group id, with the ensemble dropping incomplete groups). Signals are generated at close-of-bar and explicitly executed at a later bar open, so the contract itself encodes anti-lookahead semantics. Risk management is part of the signal: every strategy must declare ATR-scaled stops, targets, and a holding-period cap, and a unit test enforces reward/risk <= 0.85 and max_holding_hours <= 168 for all defaults. Nexus has no equivalent unified strategy contract. The ML path produces a `SignalEvent` (direction, confidence, ml_scores, features, model provenance) with no embedded stop, target, ATR basis, holding horizon, or execution timing; risk geometry is computed much later by the agent layer (A9 Trade Executor emits entry/sl/tp1-3 in a loosely typed order dict) or by the executor service. The GenAI path is even more implicit: LLM-designed "strategies" in the research registry are described in free text and mapped by keyword matching on strategy type (EMA/trend, session/breakout, mean-reversion) to hard-coded signal generators inside the evaluator — the described entry/exit logic is never actually executed as specified. Consequently Nexus cannot statically assert per-strategy risk invariants (the reference's test-time guarantee), cannot atomically couple multi-leg trades, and has a backtest/live contract mismatch because the research backtester uses fixed ATR multipliers (sl 0.75 / tp 1.8) that differ from what live agents will compute.

## Research pipeline maturity (purged walk-forward, FDR, promotion gates)

The reference's `factor_research.py` implements a research pipeline of markedly higher statistical rigor. Walk-forward folds are built with an explicit embargo gap (`embargo_bars` between train end and test start), and training rows are additionally purged by label-end time (`_label_end_time < test_start`), so no training sample's outcome window overlaps the test period. Each fold has a chronological calibration split with its own minimums, an untouched holdout segment excluded from development folds, block-bootstrap rank tests for factor significance, Benjamini-Hochberg and Benjamini-Yekutieli FDR control across the full factor family (with a check that bootstrap sample count can even resolve the first BH threshold), coverage/variance/correlation gates for feature selection, probability calibration, per-prediction economic scoring (spread, slippage, commission, historical swap/financing with provenance tags), cost-stress multipliers, and a multi-criteria promotion gate (minimum trades, minimum positive-fold fraction, per-fold profit factor, stressed compounded return > 0, plus separate data-readiness gates for discovery vs cost validation) that emits explicit verdicts such as `research_candidate_requires_paper` and `rejected_for_trading`. The long-horizon runner goes further: outcome-blind candidate freezes, pre-registration against a research registry, a complete frozen candidate declaration, and a hard list of formal-portfolio blockers that must all be resolved before PnL can exist. Nexus-ml's `WalkForwardTrainer` does rolling month-based train/validation splits and purges only the single final training timestamp (to avoid the next-bar label leak) — there is no embargo gap across the full label horizon, no calibration split, no holdout, no multiple-testing correction, and no data-readiness audit. Its promotion gate (`evaluate_promotion`) compares candidate vs incumbent on outer-validation accuracy and log-loss only, on identical folds — decent hygiene, but blind to trading economics, costs, drawdown, and regime robustness. Nexus-agents' strategy research is weaker still: LLM proposals are backtested on a single recent OHLCV window (typically a few hundred bars from a REST/Redis cache) with a fixed 1.5-pip spread, and a simple threshold gate (profit factor >= 1.4, win rate >= 0.52, Sharpe >= 0.8, >= 5 trades) promotes straight to `active`. There is no walk-forward, no purging, no FDR, no cost stress, and no untouched holdout anywhere in that path — it is an in-sample fit gate that invites overfitting, especially with an LLM free to propose until a threshold is cleared.

## Signal lifecycle (research → shadow → paper → live)

The reference institutionalizes a staged lifecycle with hard boundaries. Its research verdicts explicitly name the next stage (`research_candidate_requires_paper`), keep `approved_strategy=false` and `trading_approval=false` as immovable red lines, require fresh forward data that postdates the alpha freeze (`fresh_forward_required=true`), and refuse to even compute formal net returns until cost/financing contracts are validated (`formal_net_returns_ready=false`). Promotion to the next stage is a human-authorized, artifact-backed event, not a code default. Nexus has fragments of a lifecycle but no coherent chain. ML models: candidates train in isolated staging generations, are gated by fold-matched promotion against the incumbent, and only then atomically activate via a generation manifest — this is a genuine research→prod mechanism for models, though there is no shadow stage (a candidate never runs in parallel with the incumbent emitting side-by-side signals for A/B comparison) and no paper-trading validation window before cutover. Strategy registry statuses are `active | backtested | investigating | rejected | paused` — there is no `shadow` or `paper` state, and a strategy goes from a single-window backtest threshold directly to `active`, after which its entry/exit text is published to `strategy:active:{symbol}` for the pipeline. The one shadow-like facility is `shadow_trades.py`, which records what *rejected/downgraded* signals would have done over a ~60-minute window to validate gate thresholds — useful, but it is a counterfactual log for filters, not a staged promotion environment. Paper gating exists only at the executor boundary (`NEXUS_TRADING_MODE` defaults to `paper`; live requires explicit opt-in at process level), which is the right fail-closed default, but the paper/live switch is global and process-wide: there is no per-strategy or per-model progression from shadow→paper→live with objective graduation criteria.

## Ensemble and agent coordination

The reference coordinates strategies through a deterministic `SignalEnsembler` with per-strategy weights, minimum vote and minimum confidence thresholds, and structural integrity rules (linked multi-leg groups are dropped whole if incomplete). Coordination is transparent, testable, and side-effect free; the test suite verifies group atomicity and ensemble filtering directly. Nexus-ml's `ModelEnsemble` combines XGBoost direction, LightGBM regime (encoded as a directional hint), LSTM sequence, RF directional vote, anomaly detection, and optional sentiment via static weights, confidence thresholding, and an anomaly veto (NO_TRADE override, softened in an "aggressive" env mode). This is a reasonable voting ensemble, but weights appear fixed rather than validated per regime, the regime model is repurposed as a direction voter (a category confusion), and per-model failures are individually swallowed with warnings, so ensemble composition silently degrades. The agent layer adds a second, LLM-based coordination stack: a LangGraph pipeline of ~13 named agents (market analyst, regime, intermarket, order flow, bull/bear researchers, arbitrator, risk manager, position manager, trade executor, session governor…) with kill-switch checks, per-symbol cooldowns, orchestrator defer/claim locks (`should_defer` / `claim_active_signal` with a 120s active-signal TTL) so ML and GenAI pipelines do not fight over the same symbol, idempotent cycle state writes, and pending-delivery reclaim/DLQ handling. This operational robustness is well ahead of the reference (which has no live-service concerns at all). However, the *decision* content of the agent path is unvalidated: LLM conviction scores and arbitrator verdicts have no calibration discipline, no backtested track record gate, and no equivalence check between what agents research offline (fixed-multiplier backtests) and what they will do live. The two systems therefore differ in kind: the reference ensembles validated statistical strategies; Nexus orchestrates a fleet of models and agents whose coordination machinery is stronger than the evidence base of its components.

## Long-horizon research vs Nexus cycle cadence

The reference explicitly supports two clocks. The intraday/hourly track uses close-of-bar signals executed next open with holding caps up to a week. The slow track (`long_horizon_runner.py`) is a different animal: New York-close daily bars, decisions at the NY close with entry at the next session's open, horizons measured in sessions (multi-day to multi-month), cross-sectional centered-rank target transforms, a "require all eligible symbols or flat" missing-data rule, and a freeze pipeline that stops deliberately before portfolio PnL because execution/capital/financing contracts are not yet integrated — the module docstring documents the refusal to produce a "plausible-looking but false net-return series." Nexus is overwhelmingly short-clocked: default operational timeframe M5 (scalping), dynamic TF selection between M5/M15 based on session/volatility/spread, ML signal cooldown of 60 seconds, agent cycle cooldown of 120 seconds, cycle timeout 300 seconds, shadow-trade evaluation windows of ~60 minutes, and research re-evaluation every ~30 minutes (accelerated when a regime has no fitting active strategy, with a floor to keep heartbeats alive). Auto-retrain runs on a 24-hour cooldown over a rolling window of the last ~10k bars. There is no daily/weekly decision layer, no session-anchor discipline, no multi-session holding construct, and no concept of a frozen forward schedule. For an XAUUSD scalping deployment this may be an intentional product choice, but it means the entire slow-horizon factor class the reference treats as the primary path toward defensible alpha (carry, positioning, value/trend agreement, commodity-currency alignment — with pre-registration) has no counterpart in Nexus at all.

## Fail-closed vs fail-open defaults

The reference defaults to refusing. Trading approval flags are false and may not be flipped by agents; data discipline rules forbid opening return labels without prerequisite gates; unknown financing costs propagate as NaN rather than silently becoming zero cost (`expected_net_r` is only filled where financing is known); the long-horizon freeze raises a dedicated `FormalPortfolioNotReadyError` with an enumerated blocker list if anyone tries to convert a freeze into PnL; the OANDA adapter is hard-limited to the practice domain. Every ambiguous path terminates in denial or an explicit blocker. Nexus is mixed. Genuinely fail-closed: executor mode defaults to paper (`NEXUS_TRADING_MODE` defaults to `paper`; only `live/production/prod` enable live), kill switch halts agent cycles with NO_TRADE, synthetic metrics in the strategy evaluator are off unless `NEXUS_ALLOW_SYNTHETIC_METRICS` is explicitly set, anomaly detection vetoes to NO_TRADE, internal endpoints require a shared secret, and failed stream deliveries stay pending (retry) rather than being acked into a DLQ oblivion. Genuinely fail-open or ambiguous: when no ML model is trained the service silently falls through to a rule-based signal generator and keeps publishing BUY/SELL signals (the signal layer, not the model layer, decides there is something to trade); an unreadable active-model pointer is logged critical but the service continues on whatever loads next; per-model prediction exceptions are swallowed so the ensemble keeps voting with fewer members without a composition-health signal; most importantly, the LLM strategy research loop can promote strategies to `active` on single-window in-sample thresholds and immediately publish them as the active strategy — no paper stage, no fresh-forward requirement, no human gate. The reference would call this exactly the failure mode its red lines exist to prevent.

## Actionable Recommendations (ranked by impact)

1. **Add a paper-trading gate to the strategy lifecycle.** Introduce explicit registry statuses `shadow` and `paper` between backtest acceptance and `active`, with objective graduation criteria (minimum trades and wall-clock duration in each stage, PF/win-rate floors computed on *forward* paper fills, and a drawdown ceiling). `active` must be unreachable directly from an in-sample backtest. This closes the largest lifecycle gap versus the reference's `research_candidate_requires_paper` verdict.
2. **Replace single-window strategy evaluation with purged walk-forward.** Port the reference's fold anatomy into the nexus-agents evaluator: embargo gap sized to the strategy's max holding horizon, label-end purge, chronological calibration split, and a final untouched holdout. Report per-fold metrics and require a minimum positive-fold fraction, not just an aggregate PF — an LLM proposing until one window clears 1.4 PF is otherwise guaranteed to overfit.
3. **Introduce multiple-testing control for LLM-driven research.** Track every hypothesis/proposal evaluated (including failed rounds and improvement attempts) in a research registry with disclosed trial counts; apply BH FDR to whatever per-strategy significance test you adopt, and enforce a minimum-resamples floor like the reference does. Without trial accounting, the adaptive search loop (`run_adaptive_cycle` retrying up to N rounds until something is active) silently inflates false discoveries.
4. **Purge-and-embargo the ML walk-forward trainer.** Extend `_generate_folds` beyond the single last-timestamp purge: drop all training rows whose label end time falls inside the validation window (equivalent of the reference's `_label_end_time < test_start`), and consider a configurable embargo in bars/hours matching the next-bar labeling horizon. Also add a chronological calibration split so probability calibration is not fit on the same rows used for model selection.
5. **Make promotion economics-aware.** Extend `evaluate_promotion` beyond accuracy/log-loss: score each candidate on a simple cost-aware backtest (spread + slippage scenarios) over the same validation rows, require the candidate to beat the incumbent on net (not gross) expectancy under at least one stress multiplier, and fail the promotion to a distinct `rejected_for_cost` reason when gross improves but net does not. Mirror the reference's cost-stress ladder concept even in reduced form.
6. **Unify the strategy/signal contract across research, ML, and execution.** Define one signal value object (or event schema extension) carrying side, confidence, ATR basis, stop_atr/target_atr or absolute SL/TP, max holding horizon, execution timing (next-bar-open), strategy/generation id, and optional group_id. Require the agents' research backtester, the ML ensemble, and the trade executor to consume/produce this same schema so backtested assumptions and live orders are mechanically comparable, and so per-strategy risk invariants can be asserted in tests as the reference does.
7. **Close the fail-open holes in the ML signal path.** When no trained ensemble exists, make rule-based fallback signals explicitly tagged and, by default, non-publishable to the live verdict stream (or publish with a `fallback` flag that the risk layer treats as below threshold) rather than indistinguishable from model signals. Surface ensemble composition health (member count vs expected) so silent single-model degradation becomes an alert instead of a quiet behavior change. Keep the anomaly veto fail-closed regardless of an "aggressive" env escape hatch, or gate that hatch behind an explicit human setting recorded in runtime settings.
8. **Establish a slow-horizon research track if multi-day alpha is in scope.** Even a minimal daily NY-close pipeline (one session-anchored decision per day, multi-session holding, forward-scheduled targets frozen before evaluation, fresh-forward evidence requirement) would give Nexus a place to test carry/positioning/trend factors that the reference considers the most defensible class. If scalping-only is the deliberate product boundary, document that decision explicitly so the absence is not mistaken for an oversight.
