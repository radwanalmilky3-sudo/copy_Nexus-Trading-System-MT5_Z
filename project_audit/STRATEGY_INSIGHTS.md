# Strategy Architecture Insights (Agent A3 — Strategies)

Reference: `fx-trading-system-main/src/fx_system/` — strategies, factor research, long-horizon freeze.
Scope: principles and design decisions only; no code was copied. This is a research system, not an approved trading system.

## Strategy base-class contract and the no-look-ahead signal boundary

The strategy abstraction is deliberately minimal: a named object with a single contract that takes a mapping of symbol-to-bar-DataFrames and returns a list of typed Signal objects. The critical design decision is temporal, not computational: strategies emit signals at close-of-bar, and the execution engine only ever fills them at a later bar's open. This single rule eliminates the most common quant-research failure mode (acting on information that did not exist yet) without requiring every strategy author to reason about it — the boundary is enforced downstream in the engine, not left to per-strategy discipline.

The Signal object itself carries more than direction: confidence, ATR for risk-relative sizing, stop and target distances expressed as ATR multiples, a maximum holding period, a human-readable reason string, and an optional group identifier for multi-leg structures. By expressing risk parameters as ATR ratios rather than fixed point values, position sizing automatically adapts to volatility regimes across symbols and time. The group identifier enables the engine and ensembler to treat hedged multi-leg signals (e.g., cointegration pairs) as a single atomic position rather than two independent bets. Strategies additionally hard-gate on data validity — non-finite or non-positive ATR, or non-finite confidence, cause the signal to be dropped rather than passed through with garbage values. This fail-closed filtering at the strategy boundary prevents corrupt market data from silently propagating into position planning.

## Technical vs multicurrency strategy families

The technical family consists of single-symbol, indicator-driven setups, but each strategy is fundamentally a *regime-gated* setup rather than a naked indicator trigger. Mean reversion only fires when a trend-strength filter confirms the market is ranging; trend continuation only fires on EMA-aligned pullbacks with momentum in a neutral band; session breakout only fires when the prior Asian session range was compact and the break happens in the London window with an ATR-buffered threshold; false-breakout fades only fire when multi-day range rejection occurs outside strong trend regimes. The shared pattern is: (1) a directional condition, (2) a regime condition that can veto it, and (3) an entry-edge condition (buffer, rejection depth, separation) that also drives a calibrated confidence score. Entries trigger on state *transitions* (a level being crossed into, not merely being beyond), which prevents re-entering the same setup bar after bar.

The multicurrency family operates on the cross-section rather than the single chart. Currency-strength reversion aggregates pairwise log returns back into per-currency strength contributions via the base/quote decomposition of the currency graph, then requires *dual confirmation*: the relative strength z-score between the pair's two currencies AND the pair's own price z-score must both exceed thresholds before a signal fires. This guards against a pair looking extreme in isolation when the broader currency graph does not confirm the imbalance. The cointegration strategy uses rolling Engle-Granger testing as a periodic validity gate (re-tested every N bars, not every bar) so that spread trades are only permitted while the statistical relationship is demonstrably alive; each trade emits two opposite-side legs sharing one group identifier so downstream systems cannot execute one leg without the other. The contrast is principled: technical strategies exploit microstructure and behavioral patterns within one instrument; multicurrency strategies exploit relative-value relationships that only exist in the joint distribution of the currency universe.

## Factor research pipeline: hypothesis → purged backtest → promotion

The factor mining pipeline implements a disciplined hypothesis-testing loop with multiple layers of leakage protection. Walk-forward folds use a purged design: training rows whose label horizon would extend into the test window are removed, and an explicit embargo gap separates train from test boundaries. Within each fold's training slice, a later chronological calibration slice is held out for Platt scaling of classifier probabilities, so the trading signals use calibrated probabilities rather than raw logistic scores. Factor screening is not a simple IC threshold: it combines coverage minimums, variance and robust-scale checks, moving-block bootstrap significance clustered by feature timestamp (to respect serial correlation), and Benjamini-Hochberg (plus Benjamini-Yekutieli for dependent tests) false-discovery-rate correction across the full hypothesis family. The pipeline refuses to run with too few bootstrap samples to resolve the first BH threshold — a guard against nominally "significant" results that are actually under-powered resampling.

Economic scoring comes before any trade is emitted: each candidate prediction gets expected gross R (probability-weighted target vs. non-target mean realized R) minus estimated execution costs, financing/swap carry (with explicit provenance labels — historical as-of, configured scenario, or zero placeholder), and an extra cost buffer. Signals only fire when expected scenario net R clears a floor AND the top direction's probability clears the runner-up by a margin — a direction-confidence gap that blocks trades on ambiguous model outputs. Promotion is a multi-gate verdict, not a single score: data readiness (market-data quality, grid alignment, gap and coverage checks, source manifest and hash verification) must pass; every development fold must select features; minimum trade count, minimum positive-fold fraction, minimum per-fold profit factor, and positive compounded return under a required cost-stress multiplier (e.g., 1.5x) must all hold. Only then does the holdout — a strictly final, non-overlapping window excluded from all stability tables — get evaluated. The verdict ladder distinguishes "rejected," "needs cost validation," "needs new holdout," and "research candidate requires paper." Even the best outcome never claims profitability; it freezes a model artifact for forward paper validation.

## Long-horizon runner: outcome-blind freeze and horizon separation

The long-horizon runner implements a deliberately incomplete pipeline as a safety feature: it stops *before* portfolio PnL and refuses to fake the gap. The design recognizes that the slow-horizon label contract (decide at New York close, enter next session open, hold N sessions) is materially different from the existing portfolio runner's semantics (execute at the supplied session mark, treat targets as quantities, default missing financing to zero). Rather than adapt the existing runner and produce a plausible-looking but false net-return series, the module builds a strict common New York-close daily grid, constructs a factor-only panel, and freezes a complete predeclared set of next-open target schedules. The factor-only build is *outcome-blind by construction*: it asserts that no forward-return or label-end columns exist in the panel, and the verifier re-checks this on the written artifact.

Candidate declarations are validated against a research registry before any market outcomes are built: hypothesis IDs, expected signs, horizon sets, factor-to-hypothesis implementation mappings, registration cutoffs, and trial counts must all match the registry, and the registry itself must still declare fresh-forward-required. Directions are sourced from the frozen declaration, never from realized returns — the schedule explicitly records that provenance. The target transform is fixed and declared (cross-sectional centered ranks normalized to a unit gross per candidate-vintage), missing data flattens the entire eligible-symbol vector rather than imputing partial books, and each scheduled row carries decision time, entry-session open quote time, and scheduled-exit close quote time so the horizon separation is auditable at the timestamp level. A formal list of portfolio blockers (execution engine, quantity conversion, cost/financing contracts, slippage, commissions, capital allocation, overlapping-vintage conservation, fresh forward evidence) is embedded in the manifest, and a fail-closed assertion raises if any blocker remains. Artifacts are written atomically, hash-inventoried, symlink-rejected, and re-verified against an exact allowlist — no undeclared file may appear in a freeze directory.

## Signal aggregation, ensembling, and strategy lifecycle

The ensembler combines same-timestamp, same-symbol signals via confidence-weighted voting modulated by per-strategy weights. A minimum vote threshold rejects weak-consensus composites; a disagreement penalty discounts confidence when the remaining strategies split; and the final risk parameters (ATR, stop, target, max holding) are combined conservatively — weighted averages for distances, but the *minimum* max-holding across supporters, so a short-horizon strategy's time stop always binds. Group integrity is enforced after combination: if a multi-leg group loses any member during ensembling (e.g., one leg failed the confidence floor), the *entire group* is dropped rather than passed through unhedged. Strategy names of composites are transparently recorded, and reasons are concatenated for auditability.

The lifecycle runs research → candidate verdict → frozen model → paper, with hard state boundaries at each step. Config validation forbids a strategy from being paper-enabled without also being enabled; paper planning only emits proposals for paper-enabled strategies and warns when none exist. The system's own documentation is explicit that no strategy has been approved for trading: the OANDA adapter is restricted to practice accounts at the code level, production endpoints are forbidden, and red-line state fields (approved_strategy, trading_approval, formal_net_returns_ready, return_labels_opened) cannot be flipped by agents — only by explicit user authorization after WP6 outcome-blind freezing. Factor significance tables are labeled as research artifacts, not approval evidence; stability metrics exclude the holdout; and any claim of net returns requires both historical cost validation and a forward paper period strictly later than the alpha freeze. The research registry discloses prior trials so that multiple-testing accounting is honest rather than per-run.

## Key Principles for Nexus

For `D:\Nexus-Trading-System-MT5` (nexus-ml + nexus-agents, LLM-driven agents, paper trading):

- **Close-of-bar decisions, next-bar execution** — encode the no-look-ahead boundary in the agent/signal contract itself; strategies (human or LLM-authored) emit at bar close, execution only at later opens. Never let an agent see a bar it is trading on.
- **Signals are risk packages, not just directions** — every emitted signal should carry confidence, ATR-relative stop/target, max holding horizon, a reason string, and an optional group ID for multi-leg positions; express risk in ATR multiples so sizing survives volatility regime changes.
- **Regime-gate every setup** — technical/factor hypotheses should combine a directional condition with an explicit regime veto and an edge-threshold that also calibrates confidence; entry on state *transitions*, not persistent threshold breaches.
- **Purged walk-forward + embargo + FDR** — any LLM-generated factor or strategy hypothesis must be tested with label-horizon purging, train/test embargo gaps, block-bootstrap significance, and Benjamini-Hochberg correction across the full tried-hypothesis family; log every trial in a research registry so multiple-testing is honest.
- **Economic gate before promotion** — no signal or strategy is "good" on IC/AUC alone; require expected net R after spread, slippage, commission, and financing/swap (with explicit provenance when financing is unknown — never zero-fill missing costs silently), plus cost-stress multipliers and minimum positive-fold fractions.
- **Outcome-blind freezing for live-facing stages** — when moving from research to shadow/paper, freeze declarations (hypotheses, signs, horizons, symbol universe, cutoffs) *before* computing outcomes; build factor-only panels that structurally cannot contain label columns; hash-inventory artifacts and fail closed on any undeclared file or modified hash.
- **Ensemble conservatively with group integrity** — combine agent/strategy signals by confidence-weighted vote with a minimum-consensus threshold and disagreement penalty; use minimum holding horizon and drop entire multi-leg groups if any leg is missing, never trade partial hedges.
- **Lifecycle gates are code-enforced, not convention** — mirror the research → candidate-verdict → frozen-model → paper ladder with machine-checkable verdicts, config validation (paper flag ⊆ enabled flag), and agent-level red lines that block trading-approval state changes without explicit human authorization; paper trading remains the ceiling until forward evidence strictly after the freeze date exists.
