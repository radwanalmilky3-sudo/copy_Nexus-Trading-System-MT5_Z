# بروتوكول قناة الوكلاء — AGENT_CHANNEL

> القناة الرسمية للتكامل بين **ZAI** (المساعد السحابي Z.ai) و**OPENCODE** (الوكيل المحلي على جهاز المالك).
> المالك: radwanmhh-svg — المستودع: Nexus-Trading-System-MT5 (فرع main).
> نافذة المفعول: منذ 2026-11-05. أي تعديل على هذا الملف يتطلب موافقة المالك.

---

## 1. الهدف

- ZAI يكتب التعليمات والمستجدات وأكواد الإصلاح إلى OPENCODE، فيلتقطها ويقرأها وينفذها مباشرة.
- OPENCODE يشرح أي عمل أو مشكلة أو تعديل مطلوب → ZAI يحلها كاملة ويعدّل ويحدّث الشفرة في GitHub ويوجه التنفيذ في نفس القناة.
- القناة هي **سجل الدردشة الرسمي** بين الطرفين: كل ما يُقال بينهما يُحفظ هنا كملفات مؤرخة.

## 2. الهيكل والوظيفة

| المسار | الوظيفة | من يكتب فيه |
|---|---|---|
| `inbox/` | تعليمات وطلبات ZAI إلى OPENCODE | ZAI فقط (OPENCODE يعدّل حقل `status` وسجل التنفيذ فقط) |
| `outbox/` | ردود وتقارير وأسئلة OPENCODE إلى ZAI | OPENCODE فقط (ZAI يعدّل حقل `status` وسجل التنفيذ فقط) |
| `conversations/` | تاريخ الحوار الجاري بين الطرفين (ملف خيط واحد متجدد) | الطرفان (إلحاق فقط، لا حذف ولا إعادة كتابة لأسطر الطرف الآخر) |
| `status/` | حالة الوكيل المحلي، حالة المشروع، لوحة المهام | `AGENT_STATUS.md` = OPENCODE، `PROJECT_STATUS.md` و`TASKS.md` = ZAI (OPENCODE يقترح تعديلات عبر outbox) |
| `approvals/` | القرارات التي تحتاج موافقة المالك | ZAI ينشئها، المالك يقرر، ZAI يغلقها |
| `archive/` | الرسائل والمهام المكتملة | الطرفان (نقل فقط، لا حذف) |
| `PROTOCOL.md` | قواعد التخاطب بين الطرفين | المالك فقط |

**توضيح مهم:** `status/AGENT_STATUS.md` يعكس حالة **جهاز المالك المحلي** (أسطوله المحلي). حالة أسطول ZAI السحابي تُبلَّغ للمالك في محادثة Z.ai مباشرة، وتُذكر في رسائل inbox عند الحاجة.

## 3. صيغة الرسالة

رسالة واحدة = ملف واحد. الاسم: `MSG-YYYYMMDD-HHMM-<Z|O>NN.md` حيث `Z` = من ZAI، `O` = من OPENCODE، `NN` = تسلسل اليوم (Z001، Z002، O001...). التوقيت بتوقيت Asia/Aden (+03:00).

```markdown
---
id: MSG-20261105-1350-Z001
from: ZAI            # ZAI | OPENCODE
to:   OPENCODE       # OPENCODE | ZAI | OWNER
date: 2026-11-05T13:50:00+03:00
type: instruction    # instruction | question | report | code-fix | broadcast
priority: normal     # normal | high | critical
topic: bootstrap     # كلمة مختصرة بالإنجليزية
status: NEW          # انظر جدول الحالات
reply_to: ""         # معرّف الرسالة الأصلية إن كان ردًا
---

# العنوان

## الملخص
...

## التعليمات (مرقمة وقابلة للتنفيذ)
1. ...

## الرد المتوقع
...
```

قواعد الصيغة: حجم الرسالة ≤ 50KB. اللغة عربية والمعرفات التقنية بالإنجليزية. يُمنع وضع أي أسرار/توكنات/كلمات مرور في أي ملف من ملفات القناة.

## 4. دورة حياة الرسالة

- رسائل inbox (من ZAI): `NEW → ACK → DONE | FAILED`
- رسائل outbox (من OPENCODE): `NEW → READ → ANSWERED`
- من يغيّر الحالة: الطرف **المستقبل** فقط، عبر تعديل حقل `status` في الترويسة وإلحاق قسم في نهاية الملف:

```markdown
## سجل التنفيذ
- 2026-11-05T14:02+03:00 | OPENCODE | ACK: استلمت وبدأت التنفيذ
- 2026-11-05T14:09+03:00 | OPENCODE | DONE: نُفذت البنود 1-4، التقرير في MSG-...-O001
```

- `FAILED` يجب أن يتضمن سبب الفشل ورسالة الخطأ كاملة وآخر حالة مستقرة للنظام.
- القاعدة الزمنية: أي رسالة `NEW` عمرها > 24 ساعة بلا ACK تعتبر مهجورة → يعلّم ZAI حالتها `ARCHIVED` وينقلها إلى archive/ مع ملاحظة.

## 5. قواعد git الملزمة

1. نطاق كتابة OPENCODE في المستودع كله = **`AGENT_CHANNEL/` فقط**. أي ملف خارج هذا المجلد ممنوع الالتزام أو الدفع من طرفه.
2. قبل كل push: `git pull --rebase origin main`. يُمنع نهائيًا: `--force`، `reset --hard` على main، حذف فروع أو وسوم، merge commits إلى main.
3. تعارض rebase في ملفات القناة (نادر بالتصميم لأن الكتابة إلحاقية والمجلدات منفصلة): `git rebase --abort` ثم الانتظار لدورة قادمة (5 دقائق) والمحاولة مجددًا. لا حلول قسرية.
4. **الشفرة:** OPENCODE لا يدفع شفرة إلى GitHub إطلاقًا. إن لزم تعديل شفرة: يشرح المشكلة/العمل في outbox → ZAI يحلها كاملة، يعدّل ويحدّث الشفرة في GitHub، يوجه التنفيذ في inbox (سحب ثم إعادة تشغيل ثم تقرير). OPENCODE يجرب محليًا في فروع محلية غير مرفوعة إن شاء.
5. ZAI يلتزم بـ pull --rebase قبل كل push، ويوثّق كل تغيير شفرة في رسالة inbox وفاتورة للمالك في محادثة Z.ai.
6. رسائل الالتزام: `channel: <وصف مختصر>` لملفات القناة، وصيغة conventional commits العادية لتغييرات الشفرة من ZAI.

## 6. الدورة المجدولة (كل 5 دقائق)

دورة OPENCODE (بعد انتهاء update_nexus.bat في نفس التشغيل):
1. `git pull --rebase origin main`
2. فحص inbox/ عن أي `status: NEW` → ACK → تنفيذ البنود → DONE/FAILED مع سجل التنفيذ
3. تحديث `status/AGENT_STATUS.md` (وقت الدورة، حالة الأسطول المحلي 9000-9008، القرص، آخر commit)
4. الردود المطلوبة في outbox/ → التزام كل شيء في commit واحد `channel: cycle` → push
5. لا تغيير = لا commit ولا push (خروج صامت)

دورة ZAI (مهمة مراقبة كل 5 دقائق): fetch → قراءة outbox/ الجديدة → READ → تنفيذ/حل → رد في inbox/ → ANSWERED → push (شفرة عند اللزوم).

## 7. قواعد الأمان الحمراء (لا تُخترق)

1. لا أسرار ولا توكنات في ملفات القناة أو السجلات. التوكن في ملف خارج المستودع لا يُقرأ منه إلى أي ملف مُلتزم.
2. لا أوامر تدميرية: لا حذف بيانات Redis، لا `git push --force`، لا حذف فروع، لا إيقاف أسطول خارج أوامر التشغيل الموثقة (`run.py --paper --skip-preflight`).
3. إعادة تشغيل الأسطول المحلي: مهلة تهدئة 10 دقائق بين أي إعادتَي تشغيل، وقفل `%TEMP%\nexus_update.lock` يمنع تداخل الدورات (يُتجاهل إن تجاوز 10 دقائق).
4. أي أمر غير مفهوم أو خارج نطاق التعليمات → OPENCODE يسأل في outbox ولا يخمّن.
5. ملفات approvals/ لا يُنفَّذ منها شيء قبل ظهور قرار المالك (حقل `decision`) في الملف أو في محادثة Z.ai.

## 8. حالات الطوارئ

- `priority: critical` في inbox = توقف دورة التحديث العادية ونفّذ الفورة فورًا.
- تعطل git (فشل push متكرر > 3 دورات): OPENCODE يكتب تقريرًا في outbox ولا يلمس شيئًا حتى تصل تعليمة.
- خطر على بيانات أو أرقام حقيقية: أوقف العملية فورًا، سجّل FAILED، اكتب outbox بعنوان حاد.

## 9. الترقيم والأرشفة

- تسلسل الرسائل يبدأ من جديد كل يوم (Z001/O001 بعد منتصف الليل +03:00).
- بعد `DONE + ANSWERED` (أو `ARCHIVED`): ينقل ZAI في دورته القادمة زوج الرسالة وردّها إلى `archive/YYYY/MM/`.
- ملفات conversations/ تُدارّ عند تجاوز 200KB → تُنقل إلى archive/ باسم مؤرخ ويُفتح ملف جديد.
