D15 — إبطال خادمي للتوكن بعد logout (الخيار أ: Redis denylist)
كل توكن يولد الآن معرّف jti؛ عند logout يُضاف المفتاح nexus:auth:denylist:<jti> بمدة البقاء (TTL) المتبقية للتوكن نفسه. كل قراءة محمية عبر get_current_user تُجري فحص الإبطال وترد 401 «Token revoked (logged out)»، وقنوات WebSocket الجديدة تُرفض بالرمز 4401 إن كان jti مُبطلاً. الإبلاغ صادق: عند فشل كتابة الـdenylist يعيد logout revoked=false بدلاً من ادعاء نجاح كاذب (قراءة fail-open موثقة لضمان التوفر). التحقق الحي: logout → نفس التوكن على /me → 401، مع بقاء التوكنات الشقيقة سليمة (إبطال لكل-توكن) وتسامح ترقية للتوكنات القديمة بلا jti.
D14 — نقطة تجديد /api/v2/auth/refresh (الخيار أ)
الدخول يعيد الآن زوجاً مكتوب الأنواع (access 24h / refresh 168h) كلاهما بـjti، مع تدوير إلزامي single-use: كل استخدام للـrefresh يبطل القديم عبر الـdenylist ويولد بديلاً، وإعادة استخدام توكن مُدار تُقابَل بـ401 «Refresh token revoked»، وفشل كتابة الإبطال عند التدوير يُنهي النداء بـ503 (حد أمان لا صدار توكنات غير قابلة للإبطال). تقييد معدل مستقل 30/60s إلى جانب حارس الدخول 12/60s. الداشبورد يحتفظ بسلوكه الحالي والـrefresh متاح للاستهلاك عند الحاجة — صفر تغيير بصري.
D6 — تباعد نداءات GLM (معالجة 429 قبل فتح القاطع)
pacer على مستوى العملية بفاصل أدنى NEXUS_LLM_MIN_INTERVAL_SEC (افتراضي 1s، مدى مقيد 0–60) يُسلسل بدايات النداءات، وعند 429 backoff ×4 بسقف 32s مع تصنيف أخطاء الحصة. النتيجة: الدوران عند 429 يتحول من احتراق المحاولتين داخل النافذة المغلقة نفسها إلى انتظار هادئ واحد — والسلوك fail-closed الأصلي (NO_TRADE) يبقى حد الأمان عند استنفاد كل المحاولات. 7 اختبارات pacing جديدة تغطي الفاصل والتصنيف والسقف وإعادة ضبط الحالة.
